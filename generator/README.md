# Генератор КП (шаблон KP_2_v3)

Будує комерційну пропозицію в затвердженому дизайні `KP_2_v3` (темний HUD-стиль, A4 книжкова) з JSON-специфікації
`KpSpec` (див. `docs/CONTRACTS.md`, §5–6). Шаблон — файл користувача `templates/KP_2_v3.pptx` (КП BMF 720 у комплекті,
8 сторінок): верстка, шрифти, кольори й англійські HUD-написи лишаються, змінюється лише вміст.

## Запуск

```sh
cd generator
python3 -m kpgen --spec tests/specs/npl10_bmf750.json --out /tmp/kp           # pptx + pdf
python3 -m kpgen --spec spec.json --out /tmp/kp --no-pdf                       # лише pptx
KPGEN_BUILD=/var/lib/kp/kpgen-build python3 -m kpgen --spec spec.json --out /tmp/kp   # з кешем растрів
```

Останній рядок stdout — JSON: `{"pptx": "...", "pdf": "...", "pages": 11}`. Помилки — у stderr українською.
Коди виходу: 1 — помилка специфікації або генерації, 2 — немає візуального профілю для крана (або кран не вказано),
3 — не вдалося створити PDF (pptx уже записано).

Тривалість: pptx 1,5–4 с з кешем растрів (перша КП крана без кешу: BMF 720 — 4 с, 650 — 11 с, 750 — 25 с),
PDF 12–18 с. Розмір: pptx 12–17 МБ, PDF 4,5–5,5 МБ.

Шляхи до фото в специфікації (`rows[].photo`, `accessories[].photo`, `photos.cover` / `photos.end`) — відносно
`assets/`. Якщо файлу немає або шлях виходить за межі `assets/`, у stderr з’являється рядок `kpgen: увага: …`,
а сторінка збирається без цього фото (обкладинка й остання сторінка беруть типове фото профілю).

Потрібно: Python 3.11+ з `python-pptx`, `Pillow`, `numpy`; LibreOffice (`soffice`) для PDF; `pdftoppm` (poppler) лише для тестів.

Шрифти: у шаблоні Arial. Без Arial LibreOffice бере метрично сумісний **Liberation Sans** (пакет `fonts-liberation`),
саме з ним зроблено еталонні PDF. Растрові написи (контурна цифра моделі на обкладинці, номер на стрілі крана)
малюються `LiberationSans-Bold.ttf` (шлях можна змінити змінною `KPGEN_FONT_BOLD`).

Змінні середовища: `KPGEN_BUILD` — тека для кешу растрів (креслення, фото, фони); задайте постійну теку, тоді
перша КП кожного крана рендерить зображення, наступні беруть їх із кешу. `KPGEN_PDF_TIMEOUT` (с, типово 180),
`KPGEN_SOFFICE` — шлях до LibreOffice. Кожен експорт PDF має власний профіль LibreOffice, тож паралельні запуски не заважають один одному.

## Що з чого береться

| Сторінка | Дані зі специфікації |
|---|---|
| Обкладинка | `title`, `number`, `date`, `client.name` / `client.contact` («ПІДГОТОВЛЕНО ДЛЯ»), характеристики крана, `cover_text`, `photos.cover` |
| Маніфест, конструкція, паспорт крана | `crane.specs` (ключі з CONTRACTS §2.1), `crane.lead` / `lead2`; креслення — з профілю |
| НПЛ-10 (2 сторінки, лише `npl_crane`) | `npl.brakes`, `npl.wheels`, `npl.stakes`; решта характеристик НПЛ-10 — у `profiles.py` (з КП користувача) |
| Конфігурація | `rows` (плитки 1–8 позицій), `upgrade_chips` |
| Додаткові опції | `accessories` (до 9 карток; більше — перелік у примітці; порожньо — сторінки немає) |
| Вартість | `rows`, `total_text`, `price_date`, `valid_until`, `price_note`, `price_tags`, `terms` |
| Виробник / власне виробництво | кранові КП — сторінка BMF з шаблону; НПЛ-10 — «Виготовляємо самі» |
| Контакти | `contacts`, `maker.line`, `photos.end` |

Номери сторінок «NN / NN» і розділів «// NN — …» перераховуються після додавання чи вилучення сторінок.
Для КП НПЛ-10 рядки позицій мають ціну «у комплекті», ціну має лише разом (це задає core у `rows`).

## Новий профіль крана

Профіль — це лише візуальна частина: креслення виробника, координати підписів, номер на стрілі, типові фото.

1. Покладіть креслення bmf.ee (`*_chart.jpg`, 3308 × 2339 px; менше — збільште до цієї ширини) і фото в `assets/bmf/`.
2. У `kpgen/profiles.py` додайте словник `DRAWxxx` за зразком `DRAW650`: рамки `side` (вид збоку) і `fold` (складений кран),
   центри CAD-підписів у кожній рамці (`side_labels`, `fold_labels`; `{lift_4m_kg}` / `{lift_full_kg}` підставляються зі
   специфікації), точки осі вильоту `piv`, `tip`, `base_y`, `tip_m`, розмір `open` (5 для креслень 3308 px, 9 для збільшених).
   Необов’язково: `pass_erase` / `fold_erase` (прямокутники, які стерти з кадру), `caption_at` (куди перенести підпис
   графіка, якщо стріла його перекриває), `plate` (рамка креслення опорної плити, якщо вона інша, ніж у 720).
3. Додайте запис у `PROFILES`: `model_no` (цифри на стрілі), `draw`, `charts`, `lead`/`lead2`, `cover`/`end` для `crane_kit` і `npl_crane`
   (шлях, фокус x, y).
4. Згенеруйте КП і перегляньте сторінки «Конструкція» та «Технічний паспорт»: підписи мають лягти на розмірні лінії.
   Підберіть координати, якщо ні.

## Тести

```sh
python3 -m unittest discover -s tests -v        # перевірки рушія без PDF (~30 с)
python3 tests/build_samples.py [--orig ТЕКА] [--only npl10_bmf750] [--fresh]
```

Записує зразкові специфікації в `tests/specs/` (НПЛ-10 + BMF 750 / 720 / 650, BMF 720 у комплекті, BMF 650 у комплекті та
дві перевірки верстки: BMF 750 із 6 позиціями й опціями, BMF 650 із 2 позиціями), генерує КП, рендерить PDF і порівнює
сторінки з еталонами `kp-configurator/kp_v3_set/*.pdf`. Результат: `tests/out/report.json` і аркуші `tests/out/*_sheet.png`
(рядки: наша КП, еталон, різниця). `--orig` — друга база порівняння: PDF свіжого запуску `kp_v3_set.py` (у КП НПЛ-10 +
720 / 650 у `kp_v3_set/` лежать версії r2, зроблені до правил третього раунду: інше фото на с. 2, стара сторінка
виробництва, без сторінки опцій). `--fresh` очищає кеш растрів.
