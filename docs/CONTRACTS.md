# Contracts between components

This file is the single source of truth for the interfaces between `catalog/`, `core/`,
`server/`, `generator/`, `web/` and `android/`. A component may extend a shape (add optional
fields) but must not rename or remove anything here without updating this file in the same change.

## 0. Environment constraints (why the stack looks like this)

- The build environment has **no access to npm or PyPI**. Everything must run with what is
  already installed: Node 22 (incl. `node:sqlite`, `node:test`), TypeScript 6 (`tsc`, global),
  `@types/node` at `/opt/node-tools/node_modules/@types/node`, Python 3.13 with python-pptx,
  Pillow, numpy, Jinja2, pydantic, reportlab, requests, LibreOffice (`soffice`), Playwright +
  Chromium (`/opt/pw-browsers`).
- Therefore: **zero runtime dependencies**. Server = plain Node `node:http`. Web = TypeScript
  compiled by `tsc` to native ES modules, no framework, no bundler. Generator = Python CLI.
- `package.json` files may list `devDependencies` (`typescript`, `@types/node`) for CI, which has
  internet. Locally, `scripts/setup-local.sh` symlinks `node_modules/@types/node` to the global copy.

```ts
  origin?: string; photo_url?: string; notes?: string; needs_confirmation?: string[] }
```

Rules (`core/src/catalog.ts`):
- `Item.compatible`: every other selected item whose kind occurs in the list must be in the list; no item
  of that kind selected yet is not a conflict. Checked both ways (base ↔ crane, trailer ↔ crane).
- Accessory status for the selected items: no `compatible` → "ok"; the relevant selected items all in
  `compatible` → "ok"; else all in `compatible` ∪ `compatible_unconfirmed` → "unconfirmed" (offered, quote
  warns); else "incompatible" (validateSelection error). A variant without `compatible` fits everything.
- Accessory text (`accessoryDesc`): with a chosen variant its `desc`; otherwise `desc` + the variants that
  fit the kit ("Для BMF 750: C20, C24 або C27.") or, when the kit does not narrow them and there are ≤ 6,
  "Варіанти: …".
- `validateCatalog(catalog)` (Ukrainian messages, `[]` = valid): shapes, unique ids, every reference
  (candidates, compatible lists, bundles, presets, terms, title_slots), price rules, every preset and every
  kit default selection passes `validateSelection`, a crane `includes` a rotator and a grapple, `kp_profile`
  only on cranes and only a supported profile with the required specs, a `npl_crane` kit has exactly 2 slots,
  no "автономна гідравліка" in item title / short / desc_template, photo paths relative.
- UI helpers: `defaultSelection(kitType)`, `presetSelection(preset, catalog?)`, `slotCandidates(c, kit,
  slot, selection)` → `{id, item, allowed, reason?}[]`, `reconcileSelection(c, kit, selection, changedSlot?)`,
  `kitAccessories(c, kit, selection)` → `{accessory, status, variants, desc}[]`, `kitTitle`, `findBundle`.

```ts
  groups: Record<string, { markup_pct: number; logistics_pct: number }>;
  vat_pct: number;                 // 20

```
Defaults: groups `bmf_cranes`, `bmf_trailers`, `own_production`, `accessories` with markup and logistics 0,
metal indices `null`, buffer 0 — so KP prices are reproduced as printed. They must be set before `eur` /
`cost` prices and the metal ratio take effect (`catalog/README.md`).

## 4. Pricing (`core/src/pricing.ts`) — all results are UAH incl. VAT

`K = rate(mode) * (1 + buffer_pct/100)` where `rate` is the NBU rate or `manual_rate`.
- `eur`: `eur * K * (1 + logistics) * (1 + markup) * (1 + vat)`
- `cost`: `(Σ kg * grades[grade] + components_eur * K + hours * labor_rate + paint_uah) * (1 + markup) * (1 + vat)`
- `ref`: `uah * (eur_share * K/K_ref + metal_share * M/M_ref + (1 - eur_share - metal_share))`;
  a ratio is 1 when its reference or current value is unknown. No markup/VAT on top (ref is final).
  `K_ref = (eur_rate_ref ?? RateInfo.ref_rates[point.date]) * (1 + buffer_pct/100)`, so the buffer cancels
  for a reference price; `M_ref = metal_index_ref ?? settings.metal.ref_index_uah_per_kg`. The reference
  point is the latest of `{uah, date}` and `history[]` on or before the quote date, else the earliest one.
- `included`: 0, row text "входить у комплект"; `on_request`: no number, row text "ціна за запитом",
  excluded from the total and reported in `warnings`.
- `bundle` kits: if a `Bundle` matches the selected slot values, its price is the kit price (rows show
  "у комплекті"); otherwise the kit price is the sum of the item prices when all are known, else `null`
  with a warning. Choice price deltas and priced accessories are added on top in both cases.
- Each computed price is rounded to `rounding_uah` (whole UAH when 0). Not rounded: a `ref` price whose
  factor is exactly 1 (the KP price as printed, e.g. 59 140) and manual prices. Total = Σ rows (bundle kits:
  the kit price) + choice deltas + priced accessories; only when `discount_pct` > 0 (≤ `max_discount_pct`,
  else error) the discounted total is rounded again.
- If a needed input is missing (no EUR rate for an `eur` item, unknown grade price), the row has
  `price_uah: null` and a warning; the quote is still returned.

```ts
interface Selection { slots: Record<string, string | null>; choices: Record<string, string>;
  accessories: { id: string; price_uah?: number | null }[]; }
interface QuoteInput { kit_type: string; selection: Selection; discount_pct?: number;
  manual_prices?: Record<string, number>;   // item id -> UAH, overrides the rule
  date?: string; }                           // ISO date, default today
interface QuoteRow { no: number; item_id: string; title: string; desc: string; qty: number;
  price_uah: number | null; price_text: string; breakdown: string; }
interface Quote { kit_type: string; rows: QuoteRow[]; choices: { id: string; title: string;
  value: string; value_title: string; price_uah: number }[]; accessories: QuoteRow[];
  subtotal_uah: number; discount_pct: number; total_uah: number; eur_rate: number | null;
  eur_rate_source: string; date: string; valid_until: string; warnings: string[];
  price_display: "itemized" | "bundle"; }
```
Rules: `validateSelection(catalog, input)` returns errors in Ukrainian (unknown ids, missing
required slot, candidate not allowed, unknown choice value, incompatible accessory).

### 4.1 Pricing extensions (all optional; `core/src/types.ts`)

```ts
// signature: quote(catalog, settings, rate: RateInfo | null, input: QuoteInput): Quote  (throws QuoteError{errors})
interface RateInfo { eur: number | null; date?: string | null; source: string; fetched_at?: string | null;
  ref_rates?: Record<string, number> }     // ISO date -> EUR rate for reference points without eur_rate_ref
// Selection.accessories[]:  { id; variant?: string | null; price_uah?: number | null }  (price_uah = manual price)
// QuoteInput:  kit_price_uah?: number | null   // bundle kits: manual kit price, beats bundle and sum
// QuoteRow:    kind?, slot?, group? (accessories), photo?, variant?
// Quote:       kit_price_uah?: number | null; bundle_id?: string | null; kit_breakdown?: string;
//              complete?: boolean      // false: a position or a chosen option has no price, the total is partial
//              eur_applied?: boolean   // the current EUR rate entered at least one counted price
```
- Bundle matching: a `Bundle` applies when its `slots` equal the non-empty selected slots exactly (same keys,
  same ids); choices do not take part. Bundle kit rows show "у комплекті" with `price_uah: null`.
- Accessory rows: title "Назва: Варіант" when a variant is chosen; unpriced accessories are listed in one
  warning and stay out of the total; an "unconfirmed" accessory adds a warning.
- An option with `on_request` and no `price_uah` adds a warning and makes `complete` false.
- Missing EUR rate, missing reference rates (listed by position and date) and a missing metal index are
  reported once each in `warnings`. `refRateDates(catalog)` lists the reference dates whose EUR rate the
  server can fetch (NBU archive) and pass as `ref_rates`; `validateSettings(settings, catalog?)` checks
  PUT /api/settings bodies (incl. unknown company and price groups).

## 5. KP spec (core `buildKpSpec()` → generator input JSON)

```ts
interface KpSpec {
  template: "kp_v3";
  number: string;                  // "0007" (printed as "КП № 0007")
  date: string;                    // "18.10.2026"
  valid_until: string;             // "25.10.2026"
  client: { name: string; contact?: string };
  kit_type: string;                // "crane_kit" | "npl_crane"
  title: string;                   // "НПЛ-10 + BMF 750"
  crane: { id: string; model: string; profile: string; specs: Record<string, string>;
           lead?: string; lead2?: string } | null;
  npl: { brakes: string; wheels: string; stakes: string } | null;
  rows: { no: number; title: string; desc: string; qty: number; price_text: string;
          item_id?: string; kind?: string; photo?: string }[];
  accessories: { group: string; title: string; desc: string; photo: string; price_text: string }[];
  total_text: string;              // "1 978 000 ₴"
  price_note: string;              // "Ціни станом на 18.10.2026, курс EUR 48,10 ₴"
  maker: { name: string; line: string };
  contacts: { phones: string[]; email: string; sites: string[]; address: string; socials?: string[] };
  terms: { title: string; text: string }[];
  photos?: { cover?: string; end?: string;     // asset paths, generator falls back to profile defaults
             cover_focus?: [number, number]; end_focus?: [number, number] };  // crop focus 0..1 (x, y)
  // optional, generator defaults in brackets
  price_date?: string;             // "ЦІНИ СТАНОМ НА …" chip [date]
  cover_text?: string;             // cover lead [composed from kit type and rows]
  upgrade_chips?: string[];        // ≤ 8 "+ …" chips on the configuration page; "{opt}" → options page no.
  price_tags?: string[];           // first two chips under the price box [ПДВ + монтаж / пакет для реєстрації]
  accessories_note?: string;       // note under the accessory cards
  file?: string;                   // output base name [KP_<number>_<title>, transliterated]
}
```

How the generator (`generator/kpgen`, KP_2_v3 template) uses the fields:
- `crane.profile` picks the visual profile (`bmf650` | `bmf720` | `bmf750`, `generator/kpgen/profiles.py`);
  `crane.id` may pick a chart variant (`bmf650_plus` → BMF 650 100 kNm chart, also chosen when
  `torque_knm` is "60"). `crane.specs` keys are §2.1 plus optional `telescope` ("так" | "ні"; the
  research data keeps it outside `specs`, the catalog must copy it in); required:
  `reach_m, torque_knm, lift_4m_kg, lift_full_kg, grapple_m2, rotator_t, turn_deg`, a missing optional
  key prints "—" (no defaults are invented; a missing `slew_cyl` drops "N циліндри" from the anatomy
  page). `valve_flow_l` may be "80" or "80 л". `lead`/`lead2`: manifest page texts (profile default).
- `npl` (НПЛ-10 kits, or `kit_type: "npl_crane"`): `brakes` is the system as in the spec table
  ("гідравлічна" | "пневматична" | …), `wheels` "500/45-22,5", `stakes` "4". Row texts are not derived
  from it: the НПЛ-10 row `desc` comes from `rows` (no "автономна гідравліка" there, §business rules).
- `rows` (1–8) fill the price table and the configuration tiles in order. Tile pictures: `kind: "crane"`
  (or `item_id` = `crane.id`) → crane cut-out, `item_id` `npl*` → НПЛ-10 cut-out, `base_outriggers*`,
  `tank*`, `seat*` → the template's cut-outs, otherwise `photo` (asset path), else no picture.
- `accessories`: first 9 become cards on an extra «ДОДАТКОВІ ОПЦІЇ» page after the configuration page
  (more → listed in the note); `[]` → no page. `group` "crane" | "trailer" → «ДЛЯ КРАНА» | «ДЛЯ ПРИЧЕПА».
  `price_text` empty → "ціна за запитом".
- `valid_until` → chip «ДІЙСНА ДО …» on the price page (empty → no chip). `price_note` → text of the
  «КУРС EUR» box, a full sentence (empty → the template's sentence). `terms` (0–7) → T-01…; empty
  list keeps the template's terms.
- `maker.line` is printed after "Офіційний дистриб’ютор BMF в Україні · " on the contacts page
  (e.g. "Виробник: ТОВ «ГІДМАН»"). `contacts.address` is split into two lines after the second comma
  (or at "\n"); the footer of every page prints `sites[0]` (upper case) and `phones[0]`.
- `client.contact` is printed as a third line under the client name on the cover.

### 5.1 Building the spec (`core/src/spec.ts`)

`buildKpSpec(catalog, settings, quote, meta: KpMeta): KpSpec` throws `KpSpecError{errors}` (Ukrainian);
`kpBlockers(catalog, quote)` returns the same blockers without throwing (for the UI).

```ts
interface KpMeta { number: string; client: { name: string; contact?: string };
  maker?: string;                  // Company id, default settings.company_maker (the legal entity is selectable)
  terms?: (string | { title: string; text: string })[];   // Term ids or literal terms, default KitType.terms
  photos?: KpSpec["photos"]; accessories_note?: string; cover_text?: string; file?: string }
```
- Blockers: no crane in the kit, a crane whose `kp_profile` is not supported or that lacks a required spec,
  0 or more than 8 price rows, unknown company or term, more than 7 terms, empty number.
- `rows`: the quote rows; itemized kits also get priced choices and priced accessories (unpriced ones
  go only to `accessories`). Numbers are `"1 978 000 ₴"` with U+00A0 between groups and before ₴.
- `total_text`: "ціна за запитом" when the bundle kit has no price or no row has one.
- `date`, `valid_until` (empty when `validity_days` is 0), `price_date`: dd.mm.yyyy of the quote dates.
- `price_note`: "Ціни розраховано за курсом EUR 48,10 ₴ на 18.10.2026." when `eur_applied`, the discount
  sentence when discounted, then the text of term `eur_rate`.
- `maker.line` = `KitType.maker_line` with `{maker}` = Company.name; `contacts` from the Company.
- Every photo path (`rows[].photo`, `accessories[].photo`, `photos.cover|end`) is relative to
  `generator/assets`. A path that does not exist or leaves that folder is ignored with a warning line
  (`kpgen: увага: …`) on stderr: the tile/card goes without a picture, cover/end use the profile photo.
  `photos.*_focus` outside 0..1 → exit 1.

## 6. Generator CLI (`generator/`)

`python3 -m kpgen --spec spec.json --out DIR [--no-pdf]` (run with `cwd=generator/`).
Writes `DIR/<file>.pptx` (+ `.pdf` via `soffice --headless --convert-to pdf`) and prints exactly one
JSON line on stdout as the last line: `{"pptx": "<abs path>", "pdf": "<abs path>|null", "pages": N}`.
Exit code ≠ 0 on failure with the error on stderr. Raster work goes to `$KPGEN_BUILD` (default a
temp dir). Unsupported `crane.profile` → exit 2 with a clear message.
Exit codes: 1 invalid spec or engine error, 2 unsupported profile or `crane: null`, 3 PDF export failed
(the pptx is already written). Rasters are cached in `$KPGEN_BUILD/cache` (set it to a persistent
directory: the first KP of a crane profile renders drawings and photos, later ones reuse them).
Each PDF export uses its own LibreOffice profile; `KPGEN_PDF_TIMEOUT` (s, default 180), `KPGEN_SOFFICE`.

## 7. Server HTTP API (`server/`, default port 8080, env `PORT`)

Env: `KP_DATA_DIR` (default `./data`), `KP_ADMIN_TOKEN` (admin), `KP_ACCESS_TOKEN` (optional;
an empty value counts as unset; when set every `/api` call except `/api/health` needs `Authorization: Bearer <token>`), `KP_PYTHON`
(default `python3`), `KP_GENERATOR_DIR` (default `./generator`), `KP_CATALOG` (default
`./catalog/catalog.json`), `KP_NBU_URL` (default NBU EUR JSON endpoint), `KP_GENERATOR_TIMEOUT_S`.

| Method & path | Body / result |
|---|---|
| `GET /api/health` | `{ok:true, version}` |
| `GET /api/catalog` | Catalog |
| `GET /api/settings` | Settings |
| `PUT /api/settings` | admin only; full Settings → saved Settings (validated) |
| `GET /api/rate` | `{eur:number|null, date, source:"nbu"|"manual"|"cache"|"none", fetched_at}` |
| `POST /api/quote` | QuoteInput → Quote (400 with `{errors:[]}` on invalid selection) |
| `POST /api/kp` | `{quote_input, client, manager?, terms?}` → `{id, number, status:"queued"}` (202) |
| `GET /api/kp?q=&limit=` | journal list `[{id, number, date, client, title, total_uah, status}]` |
| `GET /api/kp/:id` | full record incl. quote snapshot, spec, status `queued|running|ready|error`, error, files |
| `GET /api/kp/:id/file/pdf` / `.../pptx` | file download (Content-Disposition) |
| `POST /api/kp/:id/recalc` | new KP from the stored quote_input with today's rate → like POST /api/kp |
| `GET /media/<path>` | images from `generator/assets` + `web/media`, strict path validation |
| `GET /*` | static files from `web/dist`, SPA fallback to `index.html` |

The journal stores the full input snapshot (quote input, settings, rate, catalog version) so a KP
can be re-rendered or recalculated. Numbers are sequential per year, zero-padded to 4 digits.
Generator runs one job at a time (queue). All errors are JSON `{error: "..."}` in Ukrainian.

## 8. Android app (`android/`) ↔ web page

The app is a full-screen WebView on the server URL the user enters (saved in the app; build-time default
`BuildConfig.SERVER_URL` from the Gradle property `kp.serverUrl`). The web app needs no Android-specific
code; everything below is optional.

- Detection: the user agent ends with ` KpAndroid/<versionName>` and `window.KpAndroid` is defined; the app
  accepts messages only from the main frame of the configured server origin.
- Downloads that work without the bridge (the app injects a helper after every page load):
  - `<a download href="blob:…|data:…">`, clicked or `a.click()` on a detached anchor: the app reads the
    blob and saves it (`URL.revokeObjectURL` is deferred 60 s for that). With `KP_ACCESS_TOKEN` on this is
    the way to download: `fetch` with the `Authorization` header → `blob()` → `a[download]` (same as in a browser).
  - plain links answered with `Content-Disposition: attachment`: the app fetches them itself with the WebView
    cookies and the last `auth` value. File name: `Content-Disposition` (`filename*=UTF-8''…` preferred), else
    the `download` attribute / `fileName`, else the URL path; MIME from `Content-Type`, else the extension.
  Then the app offers «Поділитися» (system chooser: Viber, Telegram, email…), «Відкрити», «Зберегти копію».
- `window.KpAndroid.postMessage(JSON.stringify(msg))`:

| `msg.type` | fields | effect |
|---|---|---|
| `download` | `url` (absolute or relative to the page), `fileName?`, `mime?`, `authorization?` (`"Bearer …"` or a bare token; omitted = last `auth`), `action?`: `"ask"` (default) \| `"open"` \| `"share"` | the app downloads the file and asks / opens it / opens the share chooser |
| `auth` | `authorization` (`null` or `""` clears) | sent with later downloads, only ever to the server origin |
| `settings` | — | opens the server address screen |
| `refresh` | `enabled` (boolean) | pull-to-refresh on/off (e.g. while a full-screen dialog is open) |

  `scroll`, `blob-begin`, `blob-chunk`, `blob-end`, `blob-error` are internal to the injected helper.
- Network rule (also enforced for sub-requests, service workers and downloads): HTTPS to any host; plain
  `http://`/`ws://` only to `localhost` and private IPs (10/8, 127/8, 172.16/12, 192.168/16, 169.254/16,
  100.64/10, fc00::/7, fe80::/10). Links to other origins open in the system browser; `tel:`, `mailto:`,
  `viber:`, `tg:`, `intent:` open the matching app. JavaScript, DOM storage and service workers are on
  (service workers need HTTPS or localhost, as in any browser). Invalid TLS certificates are never accepted.

## 9. Deployment (Docker image)

- `Dockerfile`: `node:22-bookworm-slim` + Debian `python3` with `python-pptx pillow numpy` (pip,
  `--break-system-packages`), `libreoffice-impress`, `poppler-utils`, fonts (Liberation = Arial metrics, also
  `liberation/LiberationSans-Bold.ttf` for kpgen; Carlito; DejaVu). Build stage: `npm ci` (or `npm install`
  without a lock file) with dev dependencies → `npm run build` → `npm prune --omit=dev`; the whole source tree
  minus `.dockerignore` (no `android/`, `docs/`, `data/`) is copied to `/app`.
- Runtime: user `node` (uid 1000), `WORKDIR /app`, `CMD ["node", "build/server/src/main.js"]`, port 8080,
  `HEALTHCHECK` = `GET /api/health` must answer 2xx. Image env: `NODE_ENV=production TZ=Europe/Kyiv PORT=8080
  KP_DATA_DIR=/data KP_CATALOG=/app/catalog/catalog.json KP_GENERATOR_DIR=/app/generator KP_PYTHON=python3
  KPGEN_BUILD=/data/kpgen-build`.
- Therefore the server must listen on all interfaces (not only 127.0.0.1), pass its environment on to the
  generator process, and write only under `KP_DATA_DIR` (and `os.tmpdir()`): `/app` is read-only for uid 1000.
- `docker-compose.yml`: service `kp`, `init: true`, env from `.env` (`KP_ADMIN_TOKEN` required,
  `KP_ACCESS_TOKEN` optional, `KP_HOST_PORT` default `8080`, e.g. `127.0.0.1:8080` behind a reverse proxy),
  volume `./data:/data` (must be writable by uid 1000).
